Tanstack의 RSC 접근법

https://tanstack.com/blog/react-server-components

"use server"와 "use client"로만 RSC 구분을 짓고 루트 컴포넌트를 기본으로 Server Component로 만들고 "use cache"와 cache component로 캐싱을 담당하는 Next.js의 접근법과 다르게 캐싱 레이어를 나누고 RSC를 React Router나 Next.js Page Router를 이용한다면 익숙한 멘탈 모델에 자신의 상황에 맞게 적용할 수 있도록 여러 기능을 제공하는 방식으로 RSC를 제공하는 접근법을 소개하는 글입니다. Tanstack Router에서의 RSC 접근법이 아직 실험 단계이지만, Next.js의 방식이 개발자들 사이에서 많은 비판과 오류에 부딫혔듯이, 새로운 RSC 접근법을 지켜볼만할 것 같습니다. 비슷하게 Next.js에서 Tanstack Start로의 마이그레이션 글도 보면 좋습니다.

좋은 아키텍쳐란?

https://tkdodo.eu/blog/the-vertical-codebase

코드에 대해 수직 구조를 어떻게 설계할지에 대해 고민거리들을 간단하게 훑어보는 글입니다. 물론 올바른 아키텍쳐는 항상 팀에 맞게, 비즈니스에 맞게 팀에서 소통해가면서 만들어가야 하므로 수직 구조를 설계하는 방식은 항상 상황에 맞게 만들어야 합니다. Atomic Design과 Feature Sliced Design은 좋은 예시가 될 수도 있지만, 은탄환이 될 수 없습니다.
