Beyond the Article: 한 걸음 더

디자이너 또한 기술적 소양을 갖춰야 한다. 그렇다면 프론트엔드 개발자는?

https://www.doc.cc/articles/craft-crisis

Figma site 사태와 여러 AI 도구의 등장은 디자이너에게 기술적 소양을 요구하고 있습니다. 하지만 이는 비단 디자이너에게만 국한된 이야기가 아닙니다. 프론트엔드 개발자 역시 마찬가지입니다. 프론트엔드 개발자가 디자인, 기획, 비즈니스 의사결정에 적극적으로 참여해야 함을 의미합니다. 더 나아가, 화면 뒤에 감춰진 백엔드와 인프라의 제약 사항을 이해하여 팀에 올바른 방향을 제시하고, 다른 동료나 AI가 작성한 코드 속에서 프론트엔드 생태계 특유의 수많은 제약사항을 예리하게 분석하고 검증해 낼 수 있어야 합니다.

React Aria는 왜 네이티브 <dialog>를 쓰지 않을까

https://github.com/adobe/react-spectrum/discussions/9696#discussioncomment-15942257

<dialog>는 모던 브라우저에서 모두 지원하는데도, 왜 React Aria같은 Headless 라이브러리들에서 사용하지 않는지, 그리고 최신 HTML, CSS 기능이 아직은 널리 적용하기엔 시기상조인지 보여주는 글입니다(ex. sonner 제작기. 그리고 마주친 문제들).

<Activity/>를 통해 자연스러운 Video 시청 경험 제공

https://www.mux.com/blog/react-is-changing-the-game-for-streaming-apps-with-the-activity-component

React 19.2에 새로 나온 <Activity/>를 통해 Video player가 가려졌을 경우에 Video 시청 경험을 자연스러운 방식으로 진행되도록 어떻게 구현하는지 소개하는 글입니다. Video가 아니더라도, DOM 상태를 저장하고 다시 재개하는데에 아주 적합한 기능으로서 알아두면 좋아보입니다. 비슷하게 React의 종료 애니메이션 문제도 같이 보면 좋습니다.

7년간의 TypeScript 마이그레이션, 어떻게 진행했는가

https://www.patreon.com/posts/seven-years-to-typescript-152144830

7년간 마이그레이션을 진행하면서 적용한 세 가지 마이그레이션 방식을 소개하면서 장단을 간단하게 소개합니다. 그리고 가장 주목할만한 AI를 통한 마이그레이션을 자세히 소개하고 있습니다. 비슷하게 Enzyme에서 RTL로, 계획적으로, 자동으로 바꾸기또한 마이그레이션을 설계하고 어떻게 마이그레이션을 이끌어갔는지 자세하게 소개하므로 한 번 보시길 추천드립니다.

AI 채팅기능을 만들 때 필요한 UX

https://medium.com/doctolib/building-reliable-ai-chat-on-mobile-01015d74422e

기본적인 채팅 기능을 만들 때와 다르게 AI 채팅 기능은 어떤 UX를 담아야 하는지, 그리고 어떻게 UX를 구현하는데 무엇이 필요했는지 소개하는 글입니다. React Native 라이브러리를 어떻게 만들었는지, Tanstack Query를 어떻게 사용했는지를 소개하는 글이지만, UX 구현 방식과 Tanstack Query의 사용법은 웹 프론트엔드에도 적용되므로 AI 채팅 UX에 관심이 있다면 보시길 추천드립니다.

JavaScript-only DRM은 의미가 없다

https://www.therantydev.com/javascript-drms-are-stupid

JS-only DRM을 리버스 엔지니어링을 하면서 하드웨어 기반 DRM이 아니라면 DRM 보안이 의미 없음을 소개하는 글입니다. DRM의 기본과 JS-only DRM을 리버스 엔지니어링하는 글이라 프론트엔드의 지식과는 약간 거리가 있지만, 기본적으로 웹 브라우저 환경이라는 클라이언트의 보안 한계를 알고 아키텍쳐링할 때 주의해야 함을 다시 상기시켜주는 글입니다.
