Tanstack Start는 차세대 Next.js의 꿈을 꾸는가

https://tanstack.com/blog/tanstack-start-5x-ssr-throughputhttps://blog.platformatic.dev/react-ssr-framework-benchmark-tanstack-start-react-router-nextjs

첫번째 글은 왜 Tanstack Start가 예전버전보다 5배 빨라졌는지, SSR 부분에서 어떤 최적화를 이뤄냈는지 보여줍니다. 이 글은 사용자 경험을 중요하게 생각해 SSR이 중요해진 지금, React/Node.js를 사용할 때 어느 부분이 최적화 가능한 부분인지, 그리고 Node.js에서 어느 부분을 주의해서 사용해야 하는지 보여줍니다. 특히 delete 연산이 V8 최적화에 미치는 영향과 연결되는 Monomorphism 개념은 참고 글과 함께 보면 좋습니다. 이어서 두 번째 글은 Platformatic팀의 벤치마크는 React 기반 메타프레임워크 중에서 Tanstack Start의 처리량이 가장 뛰어나다는 것을 보여주는 글입니다. 또한 Tanstack Start를 사용하지 않더라도, Next.js의 어떤 부분이 병목인지, 병목 구간을 측정하기 위해 어떤 도구를 썼는지 소개하므로, 같이 보면 좋습니다. 병목 구간을 정확하게 짚어낸 @plaformatic/flame과 그를 기반으로 빠른 처리량을 만들어낸 Tanstack Start를 주목해서 지켜봐야 할 것 같습니다. Next.js가 캐싱 없이 순수 SSR 처리량으로 승부하지 않는다면, 차세대 React 메타 프레임워크는 Tanstack Start가 될지도 모르겠습니다.
